## Local setup

Use a supported Node.js environment and install the locked dependencies from the repository root:

```bash
npm ci
npm run dev
```

Open `http://localhost:3000`. Product manuals live under `content/versions/v0/manuals/`; developer documentation lives under `content/versions/v0/developer/`. Update the nearest `meta.json` whenever a page is added, removed, or reordered.

## Content ownership

| Content        | Location                                 | Purpose                                                                      |
| -------------- | ---------------------------------------- | ---------------------------------------------------------------------------- |
| Manuals        | `content/versions/v0/manuals/`           | Public product behavior, role-based guidance, and canonical contracts.       |
| Developer      | `content/versions/v0/developer/`         | Engineering boundaries, implementation guidance, and contribution workflows. |
| Product status | `content/versions/v0/manuals/status.mdx` | Defined contracts, RFCs, planned work, limitations, and open decisions.      |

Keep each product rule in one canonical Manual. Developer pages may explain implementation consequences and link to the rule; they must not redefine it.

## Authoring workflow

1. Identify the canonical page and every affected cross-link.
2. Update the contract, status, examples, and Developer consequences in the same change.
3. Use the local site to review navigation, mobile readability, tables, diagrams, and heading anchors.
4. Search for stale routes and terminology before running verification.
5. Run all gates and publish one coherent commit.

## Verification

Run every gate in order before committing or publishing:

```bash
npm run lint:check
npm run format:check
npm run types:check
npm run build
```

Fix a failed gate and restart the sequence from `npm run lint:check`. Use `npm run lint:fix` and `npm run format:fix` for supported automatic fixes, then review the resulting changes before rerunning the checks.

The production build must generate routes for every page in `meta.json`. A successful type check does not prove that internal links or heading fragments are correct; inspect or automate those checks separately.
