# Product status

This documentation distinguishes settled contracts from design direction.

## Defined

| Area | Contract |
| --- | --- |
| Common resource model | Identity is `(kind, name)`; YAML is canonical; revisions, explicit includes, validation, and immutable snapshots follow the rules in this documentation. |
| `v0/site` | A stable manifest kind that composes included applications and configures shared site branding. See [v0/site](/versions/v0/manifests/v0-site). |
| `v0/translation` | A stable manifest kind for locale catalogs. See [v0/translation](/versions/v0/manifests/v0-translation). |
| `v0/application` | A stable manifest kind for application metadata, dependencies, and entry routes. See [v0/application](/versions/v0/manifests/v0-application). |

## Planned resource kinds

The following kinds are candidates for the MVP, but their manifest schemas are not defined yet:

- `v0/entity`
- `v0/page` and `v0/component`
- `v0/query` and `v0/action`
- `v0/policy`, `v0/workflow`, `v0/theme`, and `v0/navigation`

Do not treat a candidate kind as a public API until it has a dedicated reference page.

## Not defined in version 0

The translation contract does not define locale fallback, plural handling, missing-key behavior, override precedence, or how the runtime interprets optional `Trans` arguments.

Beyond the documented `{{ Trans "key" ...args }}` syntax, the platform design leaves the expression language, complete MVP kind list, exact PostgreSQL table layout, and public schema/versioning policy open.
