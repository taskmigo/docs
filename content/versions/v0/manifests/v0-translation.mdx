A `v0/translation` manifest contributes values to one locale catalog. Its common fields follow the [Resource model](/versions/v0/resources).

```yaml
kind: v0/translation
name: english

spec:
  locale: en
  content:
    applications:
      home:
        label: Home
```

## Translation fields

| Field | Rule |
| --- | --- |
| `kind` | Must be `v0/translation`. |
| `spec.locale` | Required normalized [BCP 47](https://www.rfc-editor.org/rfc/bcp/bcp47.txt) locale, such as `en`, `vi`, or `pt-BR`. |
| `spec.content` | Required object containing the values contributed to the locale catalog. Every key must be a non-empty string. |

Content values are usually strings, but objects, arrays, numbers, booleans, and `null` are valid manifest-supported values.

## Locale catalogs

`spec.locale`, rather than the manifest name, selects the catalog. Taskmigo merges all translation manifests with the same normalized locale into one effective catalog. Manifests for different locales remain separate.

The nested keys under `spec.content` form lookup paths. For example, this content defines the path `applications.home.label`:

```yaml
spec:
  locale: en
  content:
    applications:
      home:
        label: Home
```

## Use translations

Taskmigo provides two template functions:

| Function | Use it when |
| --- | --- |
| `Trans` | The translation does not depend on a quantity. |
| `TransN` | A quantity determines which plural form is selected. |

Both functions accept optional positional arguments. The translation runtime uses those values to interpolate placeholders in the resolved message.

### Translate a message with `Trans`

`Trans` resolves a key in the effective catalog for the active locale and interpolates any supplied placeholder values.

```go
func Trans(rawKey any, args ...any) string
```

| Parameter | Description |
| --- | --- |
| `rawKey` | Translation key. In manifests, write it as a quoted dotted path such as `"auth.welcome"`. |
| `args` | Optional positional values used to interpolate the message's placeholders. Pass them in the order expected by the translated message. |

```text
{{ Trans "auth.welcome" .User.Name }}
```

Here, `auth.welcome` selects the message and `.User.Name` supplies its first placeholder value. Use the function without extra arguments when the message has no placeholders:

```yaml
spec:
  label: '{{ Trans "applications.home.label" }}'
```

Use additional arguments for messages with multiple placeholders:

```text
{{ Trans "orders.summary" .User.Name .Order.Number }}
```

### Translate a plural message with `TransN`

`TransN` resolves a pluralized translation by applying the Unicode CLDR plural
rules for the active locale. CLDR compliance is mandatory: implementations must
not replace locale-specific rules with a custom binary check such as `n === 1`.

```go
func TransN(rawKey any, rawN any, args ...any) string
```

| Parameter | Description |
| --- | --- |
| `rawKey` | Translation key containing a mapping of CLDR plural categories. |
| `rawN` | Numeric quantity evaluated against the active locale's CLDR plural rules. |
| `args` | Optional positional values interpolated after the quantity. |

```text
{{ TransN "items.count" .Cart.Count .User.Name }}
```

In this example, `.Cart.Count` determines the CLDR category. The runtime also
prepends that normalized count to the formatting arguments, so the selected
message can use `%d` for the quantity. `.User.Name` is the next argument and
can be consumed by `%s`.

<Callout title="CLDR rules are required" type="warn">
  `TransN` must use the Unicode CLDR plural rules for the active locale. Do not
  assume that zero selects `zero`, that one always selects `one`, or that every
  locale has only `one` and `other`. The meaning and use of each category are
  locale-specific.
</Callout>

<Callout title="Count comes before placeholder values" type="info">
  The second argument to `TransN` is always the quantity. The runtime prepends
  it to the formatting arguments; values supplied after the count follow in
  their original order.
</Callout>

### CLDR plural catalog

A pluralized catalog value is an object keyed by CLDR category identifiers:
`zero`, `one`, `two`, `few`, `many`, and `other`. A catalog only needs
the categories used by its locale, but it must define `other` as the fallback.

```yaml
spec:
  locale: en
  content:
    items:
      count:
        one: You have %d item, %s.
        other: You have %d items, %s.
```

Languages with additional CLDR categories can define them under the same key:

```yaml
spec:
  locale: ar
  content:
    items:
      count:
        zero: You have no items, %s.
        one: You have one item, %s.
        two: You have two items, %s.
        few: You have a few (%d) items, %s.
        many: You have many (%d) items, %s.
        other: You have %d items, %s.
```

The presence of a category in a catalog does not define when it is selected.
Selection always comes from the CLDR rule for the active locale.

### Defensive behavior

| Condition | Result |
| --- | --- |
| `rawN` is not numeric | `[invalid_plural_count:key]` |
| Selected CLDR category is absent | Fall back to `other` |
| Both the selected category and `other` are absent | `[untranslated_form:key]` |
| Active locale cannot be resolved | Use the configured global fallback locale |
| Formatting fails or panics | `[translation_format_error:key]` |

### Resolution flow

<Steps>
  <Step>

  ### Select the locale catalog

  The active locale selects the effective catalog assembled from translation
  resources with the same normalized `spec.locale`.

  </Step>
  <Step>

  ### Resolve the key

  The quoted dotted key selects a message from that catalog.

  </Step>
  <Step>

  ### Select the plural form

  For `TransN`, the runtime evaluates `rawN` with the active locale's Unicode
  CLDR plural rules, then selects the matching category. If that category is
  absent, it selects `other`. `Trans` skips this step.

  </Step>
  <Step>

  ### Interpolate placeholders

  The runtime applies `args` in order to the placeholders in the resolved message,
  then returns the resulting string.

  </Step>
</Steps>

<Callout title="Translation functions are fault-tolerant" type="idea">
  `Trans` and `TransN` recover from internal panics so a translation failure does
  not crash template rendering. Treat recovery as a safety boundary, not as a
  substitute for validating translation keys and arguments.
</Callout>

## Extend a locale catalog

Create another translation manifest with a different resource name and the same locale:

```yaml
kind: v0/translation
name: english-errors

spec:
  locale: en
  content:
    errors:
      unauthorized: You do not have permission to continue.
```

This manifest adds `errors.unauthorized` to the effective `en` catalog.

## Merge rules

- Objects merge recursively.
- A path defined by only one manifest is copied to the catalog.
- Arrays and non-object values are final values; arrays are not concatenated.
- A duplicate path is an error, even when both manifests provide the same value.
- An object/non-object collision is an error.
- Results do not depend on manifest load order.

A merge error identifies the locale, conflicting path, and both source manifests. A conflict invalidates the resolved catalog.

## Validation and lookup

In addition to the [common resource validation](/versions/v0/resources), a translation manifest is invalid when its locale is missing, empty, or not normalized; `spec.content` is not an object; a content key is empty; or a value cannot be represented by the manifest format.

Version 0 does not define missing-key behavior or override precedence. `TransN` requires a configured global fallback locale for locale-resolution failures.

## Good to know

<Callout title="Resource name and locale serve different purposes" type="idea">
  The manifest `name` identifies one contribution; it does not have to match
  `spec.locale`. Resources such as `english-applications` and `english-errors` can
  contribute different paths to the same `en` catalog.
</Callout>

<Callout title="Catalogs do not use override precedence" type="info">
  Duplicate paths are errors, so independently maintained translation resources
  cannot silently replace each other's values.
</Callout>
