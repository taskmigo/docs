## Quick start

```yaml
# Catalog
kind: v0/translation
name: english-applications

spec:
  locale: en
  content:
    applications:
      home:
        label: Home
        welcome: Welcome, %s!

# Usage in another manifest
label: '{{ Trans "applications.home.label" }}'
description: '{{ Trans "applications.home.welcome" .User.Name }}'
```

<Callout title='Catalogs do not participate in imports' type='info'>
  A translation manifest may declare `imports: []` for compatibility with the common resource shape, but it cannot
  import any resource. No manifest may import `v0/translation`. Taskmigo assembles the effective catalog for the active
  locale.
</Callout>

`spec.content` defines literal catalog data; Taskmigo does not evaluate expressions inside the
catalog. Other manifests consume that data with `Trans` and `TransN`. Start with
[Expressions](/versions/v0/expressions) for the common YAML syntax and the fields that accept them.

## Create a catalog

<TypeTable
  type={{
    kind: {
      type: '"v0/translation"',

    },
    'spec.locale': {
      type: 'BCP 47 language tag',
      required: true,
      description: 'Locale served by this catalog, such as `en`, `vi`, or `pt-BR`.',
    },
    'spec.content': {
      type: 'Record<string, unknown>',
      required: true,
      description: 'Messages available through dotted lookup keys. Keys cannot be empty.',
    },
  }}
/>

`spec.locale` uses a [BCP 47](https://www.rfc-editor.org/info/bcp47/) language tag.

`spec.locale` selects the catalog; `name` identifies the contribution. All translation resources with the same normalized locale merge into one effective catalog.

Nested keys form a dotted lookup path. For example, `account.greeting` resolves this value:

```yaml
spec:
  locale: en
  content:
    account:
      greeting: Welcome back
```

Content may contain objects, arrays, strings, numbers, booleans, and `null`. A value resolved by `Trans` must be usable as a message.

## Translate a message

```text
{{ Trans "key" ...values }}
```

Values fill formatting placeholders from left to right:

```yaml
# Catalog
orders:
  summary: Order %s belongs to %s.

# Usage
{{ Trans "orders.summary" .Order.Number .User.Name }}
```

<Callout title='Pass every placeholder value' type='warn'>
  Missing values stop rendering with a runtime error. Values must also be compatible with their formatting verbs.
</Callout>

Placeholder order belongs to each translated message and may differ by locale.

## Translate a quantity

`TransN` selects a plural form using the active locale's [Unicode CLDR plural rules](https://cldr.unicode.org/index/cldr-spec/plural-rules).

```text
{{ TransN "key" count ...values }}
```

The count selects the category and fills the first compatible placeholder. Remaining values fill placeholders from left to right:

```yaml
# English catalog
spec:
  locale: en
  content:
    items:
      count:
        one: You have %d item, %s.
        other: You have %d items, %s.

# Usage
description: '{{ TransN "items.count" .Cart.Count .User.Name }}'
```

### CLDR categories

Plural objects use `zero`, `one`, `two`, `few`, `many`, and `other`. Define the categories used by the locale and always include `other`.

Category names do not imply numeric ranges: CLDR evaluates the original count for the active locale, including its decimal precision.

## Extend a catalog

Split one locale across resources when applications or domains own separate message paths:

```yaml
kind: v0/translation
name: english-errors

spec:
  locale: en
  content:
    errors:
      unauthorized: You do not have permission to continue.
```

### Merge rules

| Situation                             | Result                                                  |
| ------------------------------------- | ------------------------------------------------------- |
| Different object paths                | Merge recursively.                                      |
| A path exists in one resource         | Copy it into the effective catalog.                     |
| Arrays or non-object values           | Keep them as final values; arrays are not concatenated. |
| Two resources define the same path    | Reject the catalog, even when values match.             |
| An object and non-object share a path | Reject the catalog.                                     |

Merge results never depend on load order. Errors identify the locale, path, and both source manifests.

## Errors and fallbacks

| Condition                                        | Result                                     |
| ------------------------------------------------ | ------------------------------------------ |
| `TransN` receives a non-numeric count            | `[invalid_plural_count:key]`               |
| The selected category is missing                 | Use `other`.                               |
| The selected category and `other` are missing    | `[untranslated_form:key]`                  |
| The active locale is unavailable                 | Use the configured global fallback locale. |
| A message receives too few values                | Stop rendering with a runtime error.       |
| A value is incompatible with its formatting verb | `[translation_format_error:key]`           |

Missing-key behavior is not yet defined. See [Product status](/versions/v0/status#known-limitations-and-open-decisions).

## Validation

Beyond [common resource validation](/versions/v0/resources), a translation manifest is invalid when:

- `spec.locale` is missing, empty, or not normalized.
- `spec.content` is not an object.
- A content key is empty.
- A value cannot be represented by the manifest format.
- Multiple resources create a merge conflict.
- `imports` contains one or more entries.

Saving, updating, or deleting a translation resource revalidates snapshots that use its locale catalog.
