---
title: v0/application
description: Define application metadata and an entry route.
---

```yaml
kind: v0/application
name: home

spec:
  icon: https://example.com/images/home.png
  label: '{{ Trans "applications.home.label" }}'
  description: '{{ Trans "applications.home.description" }}'
  route: home-app
```

## Fields

| Field              | Rule                                                         |
| ------------------ | ------------------------------------------------------------ |
| `kind`             | Must be `v0/application`.                                    |
| `spec.icon`        | Required absolute image URL with a scheme and host.          |
| `spec.label`       | Required `Trans` expression for the application name.        |
| `spec.description` | Required `Trans` expression for the application description. |
| `spec.route`       | Required non-empty entry route.                              |

Locale maps cannot be embedded in the application manifest. Translation catalogs are available automatically and must not appear in `imports`. See [Translate a message](/versions/v0/manifests/v0-translation#translate-a-message).

## Imports

An application may import only lower-ranked kinds as their contracts become defined. It cannot import `v0/site`, another `v0/application`, or `v0/translation`. No lower-ranked import target is defined in v0 yet. See [Kind hierarchy](/versions/v0/resources#kind-hierarchy).

## Validation

Beyond [common resource validation](/versions/v0/resources), an application is invalid when a required field is missing, an import violates the kind hierarchy, `spec.icon` is not an absolute URL, translated metadata is not a valid `Trans` expression, or `spec.route` is empty.
