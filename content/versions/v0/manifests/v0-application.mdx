A `v0/application` defines the shared URL prefix for an application and maps imported pages to paths below that prefix.

import { TypeTable } from "fumadocs-ui/components/type-table";

```yaml
kind: v0/application
name: home

imports:
  - v0/page/index

spec:
  icon: https://example.com/images/home.png
  label: '{{ Trans "applications.home.label" }}'
  description: '{{ Trans "applications.home.description" }}'
  path: /home

  routes:
    - page: v0/page/index
      path: /
```

The example exposes `v0/page/index` at `<host>/home/`.

Locale maps cannot be embedded in the application manifest. Translation catalogs are available automatically and must not appear in `imports`. See [Translate a message](/versions/v0/manifests/v0-translation#translate-a-message).

`spec.label` and `spec.description` accept the full Taskmigo Expression syntax and must render a
string. Other Application fields are literal values. See
[Expressions](/versions/v0/expressions#support-and-context-by-manifest-kind) for YAML quoting,
functions, and context rules.

## Paths and routes

`spec.path` establishes the application's path below the host. Each `spec.routes[].path` is resolved below that application path.

| Application path | Page path   | Result                 |
| ---------------- | ----------- | ---------------------- |
| `/home`          | `/`         | `<host>/home/`         |
| `/home`          | `/settings` | `<host>/home/settings` |

A page path of `/` designates the index page for the application path. Application paths and page paths must begin with `/`; they are paths, not absolute URLs.

## Imports

Only an application may import a page, and an application's `imports` entries may target only `v0/page`. Importing a page makes it available to the application; it does not expose the page until a matching entry appears in `spec.routes`.

Every routed page must be imported. Page resources are not discovered by name. See [Resource model](/versions/v0/resources#imports).

## Validation

Beyond [common resource validation](/versions/v0/resources), an application is invalid when:

- A required field is missing.
- `imports` is missing, empty, contains a duplicate identity, or targets a kind other than `v0/page`.
- `spec.icon` is not an absolute URL.
- An Expression in translated metadata has invalid template syntax, cannot be evaluated, or does not
  render a string.
- `spec.path` or a page path does not begin with `/`.
- `spec.routes` is empty, repeats a path, or references a page absent from `imports`.
