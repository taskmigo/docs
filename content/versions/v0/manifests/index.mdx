Manifests describe the resources that make up a Taskmigo system. Start with the outcome you want,
then open the matching reference for a complete example, its `spec` fields, and validation rules.

| I want to…                                       | Use this manifest                                                       |
| ------------------------------------------------ | ----------------------------------------------------------------------- |
| Compose applications and set shared branding     | [Site (`v0/site`)](/versions/v0/manifests/v0-site)                      |
| Group pages under a path and assign their routes | [Application (`v0/application`)](/versions/v0/manifests/v0-application) |
| Build an interface from registered components    | [Page (`v0/page`)](/versions/v0/manifests/v0-page)                      |
| Add translated messages for a locale             | [Translation (`v0/translation`)](/versions/v0/manifests/v0-translation) |

Shared identity, version, import, and revision rules live in the
[Resource model](/versions/v0/resources). When you are ready to write YAML, enable
[JSON Schema and autocomplete](/versions/v0/manifests/autocomplete) for editor suggestions and
inline validation.

See [Product status](/versions/v0/status) for planned manifest types and open decisions.
