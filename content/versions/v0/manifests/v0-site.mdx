---
title: v0/site
description: Compose applications and define shared site branding.
---

A `v0/site` is the composition root. It imports applications, selects which ones to expose, and defines shared brand assets.

<Callout title="One Site per system" type="warn">
  A valid Taskmigo system contains exactly one logical Site resource. It may have multiple
  revisions, but a different name or schema prefix cannot create another Site.
</Callout>

Its `imports` entries may target only `v0/application`. Translation catalogs are attached automatically and must not be imported.

```yaml
kind: v0/site
name: root

imports:
  - v0/application/home
  - v0/application/admin

spec:
  brand:
    label: Taskmigo
    logo: ./logo.png
    favicon: ./favicon.ico

  applications:
    - home
    - admin
```

## Fields

| Field                | Rule                                                |
| -------------------- | --------------------------------------------------- |
| `kind`               | Must be `v0/site`.                                  |
| `spec.brand`         | Required branding configuration.                    |
| `spec.brand.label`   | Required site label.                                |
| `spec.brand.logo`    | Required logo path.                                 |
| `spec.brand.favicon` | Required favicon path.                              |
| `spec.applications`  | Required ordered list of exposed application names. |

## Expose applications

Each name in `spec.applications` must have a matching `v0/application/<name>` import. List order controls display order; importing an application alone does not expose it.

## Validation

Beyond [common resource validation](/versions/v0/resources), a site is invalid when another logical Site exists in the system, an import does not target `v0/application`, branding or a required brand field is missing, an application name is duplicated, or an exposed application has no matching import.
