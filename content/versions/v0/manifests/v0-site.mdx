---
title: v0/site
description: Compose applications and define shared site branding.
---

A `v0/site` manifest is the composition root for a Taskmigo site. It selects the applications exposed by the site and defines shared brand assets. Its common fields follow the [Resource model](/versions/v0/resources).

```yaml
kind: v0/site
name: root

includes:
  - kind: v0/application
    name: home

spec:
  brand:
    label: Taskmigo
    logo: ./logo.png
    favicon: ./favicon.ico

  applications:
    - home
```

## Site fields

| Field | Rule |
| --- | --- |
| `kind` | Must be `v0/site`. |
| `spec.brand` | Required site-branding configuration. |
| `spec.brand.label` | Required label for the site brand. |
| `spec.brand.logo` | Required path to the site logo. |
| `spec.brand.favicon` | Required path to the site favicon. |
| `spec.applications` | Required ordered list of application names exposed by the site. |

## Applications

The site exposes an application only when both of the following are true:

1. `includes` contains the application as `kind: v0/application`.
2. `spec.applications` contains the application's name.

```yaml
includes:
  - kind: v0/application
    name: home
  - kind: v0/application
    name: admin

spec:
  brand:
    label: Taskmigo
    logo: ./logo.png
    favicon: ./favicon.ico

  applications:
    - home
    - admin
```

The order in `spec.applications` is preserved.

## Validation

In addition to the [common resource validation](/versions/v0/resources), a site is invalid when its brand configuration or a required brand field is missing, an application name is duplicated, or an application in `spec.applications` has no matching `v0/application` include.

## Good to know

<Callout title="Included does not mean exposed" type="idea">
  `includes` makes a dependency available. `spec.applications` decides which
  applications the site exposes and in what order. Including an application alone
  does not expose it.
</Callout>
