A `v0/site` is the composition root. It imports Applications, selects which ones to expose, and defines shared brand assets.

<Callout title='One Site per system' type='warn'>
  A valid Taskmigo system contains exactly one logical `site` resource. `apiVersion` is not part of resource identity,
  so migrating that Site to another contract version does not create another composition root.
</Callout>

Its `imports` entries may target only `application` resources. Translation catalogs are attached automatically and must not be imported.

```yaml
apiVersion: v0
kind: site

metadata:
  name: root

imports:
  - application/home
  - application/admin

spec:
  brand:
    label: Taskmigo
    logo: ./logo.png
    favicon: ./favicon.ico

  applications:
    - home
    - admin
```

## Expose applications

Each name in `spec.applications` must appear once and have a matching `application/<name>` import. List order controls display order; importing an Application alone does not expose it.
