---
title: Page
description: Define page metadata and a declarative component tree.
---

A `v0/page` builds one user interface from an ordered tree of registered components. It owns the page title, description, and content; an Application decides where users can open it.

import { TypeTable } from 'fumadocs-ui/components/type-table';

```yaml
kind: v0/page
name: index

spec:
  meta:
    title: '{{ Trans "pages.index.meta.title" }}'
    description: '{{ Trans "pages.index.meta.description" }}'

  body:
    - component: Stack
      props:
        data-component-id: container
      children:
        - component: Typography
          props:
            variant: h1
          children: Hello World
```

A page does not define a route. Route ownership belongs to the importing [v0/application](/versions/v0/manifests/v0-application).

## Component nodes

Every node names a registered component and provides the props and children accepted by that component:

```yaml
component: Stack
props:
  data-component-id: example
children: []
```

Component names are case-sensitive: `Stack` and `stack` are different names. The initial contract defines [Stack](/versions/v0/ui-components/stack) for grouping content and [Typography](/versions/v0/ui-components/typography) for rendering text. Additional components and props may be added in future contract revisions.

A Page can declare built-in components directly, as in the first example. Reuse is optional: import a [`v0/component`](/versions/v0/manifests/v0-component) only when multiple places should share the same component tree. Use its full resource reference as the node's `component` value and pass values declared by the Component through `props`:

```yaml
imports:
  - v0/component/header

spec:
  body:
    - component: v0/component/header
      props:
        title: Hello World
```

Page imports may target Pages and reusable Components. Every reusable Component used in `spec.body` must appear in `imports`; built-in components such as `Stack` and `Typography` do not require imports. Each node must satisfy the selected component's contract.

## Workflow discovery (RFC)

<Callout title='RFC integration' type='warn'>
  The [`v0/workflow` RFC](/versions/v0/manifests/v0-workflow) proposes an additional Page import relationship. It is not part of the supported Page contract yet.
</Callout>

Under the RFC, a Page imports every Workflow that users may discover or start from that Page:

```yaml
kind: v0/page
name: operations

imports:
  - v0/workflow/employee-onboarding
  - v0/workflow/access-review

spec:
  # Page UI
```

The import is an authorization-independent discovery boundary: it makes the Workflow available to Page runtime UI, but it does not itself grant permission to execute it. The Page UI starts and observes executions through the same Workflow execution service used by API clients; there is no Page-only execution path.

A Page does not embed Workflow steps in `spec.body`, and a Workflow does not embed a Page. Interactive Workflow steps reuse imported `v0/component` resources. See [Page integration](/versions/v0/manifests/v0-workflow#page-integration) for the proposed end-to-end contract.
