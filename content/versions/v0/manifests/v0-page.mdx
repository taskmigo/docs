---
title: v0/page
description: Define page metadata and a declarative component tree.
---

A `v0/page` describes one user interface as metadata and an ordered tree of registered components. An application imports the page and assigns its route.

```yaml
kind: v0/page
name: index

spec:
  meta:
    title: '{{ Trans "pages.index.meta.title" }}'
    description: '{{ Trans "pages.index.meta.description" }}'

  body:
    - component: Stack
      props:
        data-component-id: container
      children:
        - component: Typography
          props:
            variant: h1
          children: Hello World
```

## Fields

| Field                   | Rule                                      |
| ----------------------- | ----------------------------------------- |
| `kind`                  | Must be `v0/page`.                        |
| `spec.meta`             | Required page metadata.                   |
| `spec.meta.title`       | Required string or `Trans` expression.    |
| `spec.meta.description` | Required string or `Trans` expression.    |
| `spec.body`             | Required ordered list of component nodes. |

A page does not define a route. Route ownership belongs to the importing [v0/application](/versions/v0/manifests/v0-application).

## Component nodes

Every node has a registered component name, optional component-specific props, and content accepted by that component:

```yaml
component: Stack
props:
  data-component-id: example
children: []
```

Component names are case-sensitive. The initial contract defines [Stack](/versions/v0/ui-components/stack) and [Typography](/versions/v0/ui-components/typography). Additional components and props may be added in future contract revisions.

## Validation

Beyond [common resource validation](/versions/v0/resources), a page is invalid when:

- `imports` contains an entry.
- A required metadata or body field is missing.
- `spec.body` is not a list.
- A component name uses incorrect casing, is not registered, or its node does not satisfy that component's contract.
