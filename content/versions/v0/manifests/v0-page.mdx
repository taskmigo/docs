A `v0/page` builds one user interface from an ordered tree of registered components. It owns the
page title, description, and content; an Application decides where users can open it.

import { TypeTable } from 'fumadocs-ui/components/type-table';

```yaml
kind: v0/page
name: index

spec:
  meta:
    title: '{{ Trans "pages.index.meta.title" }}'
    description: '{{ Trans "pages.index.meta.description" }}'

  body:
    - component: Stack
      props:
        data-component-id: container
      children:
        - component: Typography
          props:
            variant: h1
          children: Hello World
```

A page does not define a route. Route ownership belongs to the importing [v0/application](/versions/v0/manifests/v0-application).

## Component nodes

Every node names a registered component and provides the props and children accepted by that
component:

```yaml
component: Stack
props:
  data-component-id: example
children: []
```

Component names are case-sensitive: `Stack` and `stack` are different names. The initial contract
defines [Stack](/versions/v0/ui-components/stack) for grouping content and
[Typography](/versions/v0/ui-components/typography) for rendering text. Additional components and
props may be added in future contract revisions.

A Page can declare built-in components directly, as in the first example. Reuse is optional: import
a [`v0/component`](/versions/v0/manifests/v0-component) only when multiple places should share the
same component tree. Use its full
resource reference as the node's `component` value and pass values declared by the Component through
`props`:

```yaml
imports:
  - v0/component/header

spec:
  body:
    - component: v0/component/header
      props:
        title: Hello World
```

Every reusable Component used in `spec.body` must appear in the Page's `imports`. Built-in
components such as `Stack` and `Typography` do not require imports.

Expression support is declared in each field or component Type Table note. See
[Expressions](/versions/v0/expressions) for syntax, functions, and context values.

## Validation

Beyond [common resource validation](/versions/v0/resources), a page is invalid when:

- `imports` targets a kind other than `v0/component` or repeats the same Component identity.
- A required metadata or body field is missing.
- `spec.body` is not a list.
- A component name uses incorrect casing, is not registered, or its node does not satisfy that component's contract.
- A reusable Component is used without being imported, or its `props` do not satisfy the
  Component's prop declarations.
