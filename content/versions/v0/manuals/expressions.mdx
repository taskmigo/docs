title: Expressions
description: Use backend-evaluated dynamic values in fields that explicitly support Expressions.

Taskmigo Expressions use [Apache FreeMarker Template Language](https://freemarker.apache.org/docs/dgui_template_exp.html). A field exposes only its documented context values and Taskmigo functions; Expressions cannot access arbitrary Java objects, methods, files, network resources, or environment state.

<Callout title='Backend-only execution' type='info'>
  Expressions are evaluated by the Taskmigo backend. React/Next.js receives resolved values; browser-only context and
  frontend Expression evaluation are not part of the defined contract.
</Callout>

## Start here

Use `${...}` for a dynamic value and quote the complete YAML value:

```yaml
label: '${Trans("applications.home.label")}'
```

When the complete YAML value is one interpolation, Taskmigo preserves the evaluated type:

```yaml
when: '${step.output.approved}'
```

Literal text around an interpolation produces a string:

```yaml
label: 'Welcome to ${This.name}!'
```

Non-string fields require exactly one interpolation whose result matches the field type. FreeMarker directives such as `<#if>` and `<#list>` are valid only where the field accepts rendered text or nodes.

## Where Expressions are allowed

A manifest field supports Expressions only when its Type Table shows the Expression marker. Syntax support does not grant access to every context variable: the field contract decides which values and functions are visible.

## Taskmigo functions

| Function                         | Returns | Purpose                                                            |
| -------------------------------- | ------- | ------------------------------------------------------------------ |
| `Trans(key[, value...])`         | string  | Resolve one message and fill placeholders.                         |
| `TransN(key, count[, value...])` | string  | Select a plural form for the bound locale, then fill placeholders. |

Translation catalog structure, plural behavior, and fallback rules are defined by [Translation](/versions/v0/manuals/manifests/v0-translation).

## Defined context values

### Global context

| Value              | Meaning                            |
| ------------------ | ---------------------------------- |
| `Runtime.Hostname` | Hostname at evaluation time.       |
| `This.kind`        | Current manifest kind.             |
| `This.name`        | Current manifest name.             |
| `This.version`     | Current manifest contract version. |
| `This.revision`    | Current manifest revision.         |

### Component template context

An imported reusable Component can read only props declared by its own `spec.props` contract:

```yaml
children: '${props.title}'
```

Use `props.<name>` inside `Component.spec.template`.

<Callout title='Workflow context is an RFC' type='warning'>
  `input`, `steps`, `step.input`, and `step.output` belong to the proposed Workflow contract. They are documented in
  [Workflow — Expressions and data flow](/versions/v0/manuals/manifests/v0-workflow#expressions-and-data-flow) and are
  not available runtime context until Workflow is delivered.
</Callout>

## Stable presentation context

Backend evaluation uses the presentation context captured by the browser runtime binding. In particular, `Trans` and `TransN` use the bound locale instead of rereading mutable profile language on every navigation.

See [Runtime lifecycle](/versions/v0/manuals/runtime#browser-runtime-binding) for tab isolation, reload behavior, and explicit presentation changes.

## Operators and built-ins

_The example prop names below are illustrative._

| Need               | Syntax                           | Example                                |
| ------------------ | -------------------------------- | -------------------------------------- |
| Boolean conditions | `&&`, `\|\|`, `!`                | `${props.enabled && props.visible}`    |
| Compare values     | `==`, `!=`, `<`, `<=`, `>`, `>=` | `${props.variant == "primary"}`        |
| Count a sequence   | `?size`                          | `${props.items?size}`                  |
| Select a value     | `[index]`                        | `${props.items[0]}`                    |
| Select a range     | `[start..end]`                   | `${props.items[0..1]}`                 |
| Test membership    | `?seq_contains(value)`           | `${props.roles?seq_contains("admin")}` |
| Supply a default   | `value!fallback`                 | `${props.subtitle!"Untitled"}`         |
| Test availability  | `value??`                        | `${props.subtitle??}`                  |
| Combine text       | `+`                              | `${"Hello, " + props.name}`            |

A field may expose a narrower Expression profile. The proposed Policy contract has its own restricted [predicate subset](/versions/v0/manuals/manifests/v0-policy#available-predicates).

## Text directives

String and node fields may use permitted FreeMarker directives:

| Need               | Example                                         |
| ------------------ | ----------------------------------------------- |
| Store a value      | `<#assign title = props.title>${title}`         |
| Conditional text   | `<#if props.active>Active<#else>Inactive</#if>` |
| Iterate a sequence | `<#list props.items as item>${item}</#list>`    |

Taskmigo validates syntax, visible context, functions, and expected result type before activation whenever the required values are known. Values that exist only at runtime are checked again during backend evaluation.

## Authoring checklist

1. Quote YAML values containing FreeMarker syntax.
2. Use only context values and functions exposed by the field.
3. For a non-string result, use exactly one interpolation and return the field's declared type.
