---
title: Expressions
description: Put dynamic text or typed values into fields that accept an Expression.
---

Taskmigo Expressions use [Apache FreeMarker Template Language](https://freemarker.apache.org/docs/dgui_template_exp.html). A field exposes only its documented context values and Taskmigo functions; Expressions cannot access arbitrary Java objects, methods, files, network resources, or environment state.

> **v0 execution boundary:** Expressions are evaluated only by the Taskmigo backend. Frontend runtimes, including React/Next.js, receive resolved values and must not evaluate Expression source themselves. Frontend-only context variables and browser-side Expression evaluation are not part of the v0 contract.

## Start here

Use `${...}` for a dynamic value and quote the complete YAML value:

```yaml
spec:
  label: '${Trans("applications.home.label")}'
```

Here, `'...'` is the YAML string, `${...}` is the FreeMarker interpolation, and `Trans` is a Taskmigo function.

When the YAML value is exactly one interpolation, Taskmigo preserves its evaluated type. This allows a boolean field, for example, to receive a boolean instead of the text `"true"`:

```yaml
when: '${step.output.approved}'
```

Literal text around an interpolation produces a string:

```yaml
label: 'Welcome to ${This.name}!'
```

FreeMarker directives such as `<#if>` and `<#list>` are therefore valid only where the field accepts rendered text or nodes. Non-string fields require exactly one interpolation whose result matches the declared field type.

## Use Taskmigo functions

These are the global Taskmigo functions. A field-specific page documents any additional function exposed only in that field.

| Function                         | Returns | Use                                                                                        |
| -------------------------------- | ------- | ------------------------------------------------------------------------------------------ |
| `Trans(key[, value...])`         | string  | Resolves a catalog key; additional arguments fill message placeholders from left to right. |
| `TransN(key, count[, value...])` | string  | Selects the locale's plural form for `count`, then fills its message placeholders.         |

```yaml
description: '${Trans("applications.home.description")}'
itemCount: '${TransN("cart.items", 3)}'
```

For catalog structure, placeholders, plural rules, fallbacks, and errors, see [Translation](/versions/v0/manuals/manifests/v0-translation).

## Use context values

Context values are available only where the field contract exposes them. In v0, every context value must be available to backend evaluation; browser-only state is not an Expression context.

| Value                  | Available in              | Returns                                            |
| ---------------------- | ------------------------- | -------------------------------------------------- |
| `Runtime.Hostname`     | Any Expression            | Hostname at evaluation time.                       |
| `This.kind`            | Any Expression            | Current manifest kind.                             |
| `This.name`            | Any Expression            | Current manifest name.                             |
| `This.version`         | Any Expression            | Current manifest version.                          |
| `This.revision`        | Any Expression            | Current manifest revision.                         |
| `props.<name>`         | Component `spec.template` | A prop passed to that Component.                   |
| `input.<name>`         | Workflow execution        | Input captured when execution started.             |
| `steps["<id>"].output` | Workflow execution        | Persisted output of a completed or continued step. |
| `steps["<id>"].status` | Workflow execution        | Persisted runtime status of that step.             |
| `step.input`           | Current Workflow step     | Input resolved for the step being evaluated.       |
| `step.output`          | Workflow navigation       | Current step output used to select the next edge.  |

Use bracket access when a dynamic key is not a valid FreeMarker identifier, as with a Workflow step ID containing `-`. Names and paths are case-sensitive.

## Use operators and built-ins

_The names below are illustrative. A Component can access only props declared by its own contract._

The default Expression profile supports the operators and built-ins below. A field may expose a narrower profile; Policy has its own [restricted predicate list](/versions/v0/manuals/manifests/v0-policy#available-predicates).

| Need                       | Syntax                           | Example                                |
| -------------------------- | -------------------------------- | -------------------------------------- |
| Combine boolean conditions | `&&`, `\|\|`, `!`                | `${props.enabled && props.visible}`    |
| Compare values             | `==`, `!=`, `<`, `<=`, `>`, `>=` | `${props.variant == "primary"}`        |
| Count a sequence           | `?size`                          | `${props.items?size}`                  |
| Select one value           | `[index]`                        | `${props.items[0]}`                    |
| Select a range             | `[start..end]`                   | `${props.items[0..1]}`                 |
| Test membership            | `?seq_contains(value)`           | `${props.roles?seq_contains("admin")}` |
| Provide a default          | `value!fallback`                 | `${props.subtitle!"Untitled"}`         |
| Test availability          | `value??`                        | `${props.subtitle??}`                  |
| Combine text               | `+`                              | `${"Hello, " + props.name}`            |

## Render text with directives

String and node fields may use the following FreeMarker directives as well as interpolation:

| Need                        | Syntax example                                  |
| --------------------------- | ----------------------------------------------- |
| Store and reuse a value     | `<#assign title = props.title>${title}`         |
| Render a conditional branch | `<#if props.active>Active<#else>Inactive</#if>` |
| Iterate a sequence          | `<#list props.items as item>${item}</#list>`    |

Taskmigo validates the syntax, available data model, functions, and expected result type before activation whenever all required values are known. Runtime-only values are checked again during backend evaluation.

For SSR, the backend evaluates every Expression needed for the requested render using the acquired snapshot and server-visible runtime context before the render model is returned to Next.js. The render model contains the resulting values, not Expression programs intended for browser execution.

## Before you save

1. Quote YAML values containing FreeMarker syntax.
2. Use only context values and functions exposed by that field.
3. For a non-string result, use exactly one `${...}` interpolation.
4. Ensure the evaluated result matches the field's declared type.
