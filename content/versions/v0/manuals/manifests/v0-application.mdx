title: Application

An Application owns one origin-relative URL prefix and maps imported Pages below it.

```yaml
apiVersion: v0
kind: application
metadata:
  name: home
imports:
  - page/index
spec:
  icon: https://example.com/images/home.png
  label: '${Trans("applications.home.label")}'
  description: '${Trans("applications.home.description")}'
  path: /home
  routes:
    - page: index
      path: /
```

This exposes Page `index` at `/home/` on the current host.

## Paths and routes

Taskmigo combines the Application prefix with the route path:

| `spec.path` | `routes[].path` | Resulting URL path |
| ----------- | --------------- | ------------------ |
| `/home`     | `/`             | `/home/`           |
| `/home`     | `/settings`     | `/home/settings`   |

A route path is **not** an independent absolute URL. It is interpreted below `spec.path`.

Every routed Page must appear in `imports`; importing a Page alone does not expose a route. `imports` and `spec.routes` cannot be empty, and the resulting routes must be unique.

See [Resource references](/versions/v0/manuals/resources#references) for import syntax and revision selection.
