A Page owns what is rendered. Its importing Application owns where the Page is routed.

```yaml
apiVersion: v0
kind: page
metadata:
  name: index
spec:
  meta:
    title: '${Trans("pages.index.meta.title")}'
    description: '${Trans("pages.index.meta.description")}'
  body:
    - component: Stack
      props:
        data-component-id: container
      children:
        - component: Typography
          props:
            variant: h1
          children: Hello World
```

A Page does not define a route. See [Application paths and routes](/versions/v0/manuals/manifests/v0-application#paths-and-routes).

## Component nodes

A component node selects one built-in UI Component or one imported reusable Component and supplies the values accepted by that component.

```yaml
component: Stack
props:
  data-component-id: example
children: []
```

Built-in names are case-sensitive. The defined UI set currently contains [Stack](/versions/v0/manuals/ui-components/stack) and [Typography](/versions/v0/manuals/ui-components/typography); built-ins do not require imports.

## Reuse a Component

Import a reusable [Component](/versions/v0/manuals/manifests/v0-component), use its `metadata.name` as the node's `component`, and pass values through `props`.

```yaml
imports:
  - component/header

spec:
  body:
    - component: header
      props:
        title: Hello World
```

Every reusable Component used by the Page must appear in `imports`. The selected Component validates required, optional, defaulted, and typed props.

<Callout title='Workflow integration is an RFC' type='warning'>
  The proposed Workflow contract allows Pages to import Workflows that users can discover and start. That behavior is
  not part of the currently available runtime. See [Workflow — Page
  integration](/versions/v0/manuals/manifests/v0-workflow#page-integration).
</Callout>
