---
title: Page
description: Define page metadata and a declarative component tree.
---

A `v0/page` builds one user interface from an ordered tree of registered components. It owns the page title, description, and content; an Application decides where users can open it.

import { TypeTable } from 'fumadocs-ui/components/type-table';

```yaml
apiVersion: v0
kind: page

metadata:
  name: index

spec:
  meta:
    title: '{{ Trans "pages.index.meta.title" }}'
    description: '{{ Trans "pages.index.meta.description" }}'

  body:
    - component: Stack
      props:
        data-component-id: container
      children:
        - component: Typography
          props:
            variant: h1
          children: Hello World
```

A Page does not define a route. Route ownership belongs to the importing [Application](/versions/v0/manuals/manifests/v0-application).

## Component nodes

Every node names a registered component and provides the props and children accepted by that component:

```yaml
component: Stack
props:
  data-component-id: example
children: []
```

Component names are case-sensitive: `Stack` and `stack` are different names. The initial contract defines [Stack](/versions/v0/manuals/ui-components/stack) for grouping content and [Typography](/versions/v0/manuals/ui-components/typography) for rendering text. Additional components and props may be added in future contract revisions.

A Page can declare built-in components directly, as in the first example. Reuse is optional: import a [Component](/versions/v0/manuals/manifests/v0-component) only when multiple places should share the same component tree. Use its name as a node's `component` value and pass values declared by the Component through `props`:

```yaml
imports:
  - component/header

spec:
  body:
    - component: header
      props:
        title: Hello World
```

Every reusable Component used in `spec.body` must appear in `imports`; built-in components such as `Stack` and `Typography` do not require imports. Each node must satisfy the selected component's contract.

A Page may also import [Workflow](/versions/v0/manuals/manifests/v0-workflow) resources that users can discover and start from that Page:

```yaml
imports:
  - component/header
  - workflow/employee-onboarding
```

Importing a Workflow exposes it to Page runtime UI but does not itself grant permission to execute it. Pages do not embed Workflow steps in `spec.body`; interactive Workflow steps reuse Components imported by the Workflow itself. See [Reference ability](/versions/v0/manuals/resources#reference-ability) for the complete import matrix.
