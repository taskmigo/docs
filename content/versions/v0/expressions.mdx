title: Expressions

An Expression is a YAML string that Taskmigo evaluates dynamically. Any field whose contract
accepts an Expression accepts the complete Taskmigo Expression syntax. The field determines the
expected result type; the manifest context determines which data is available during evaluation.

## Start with one Expression

This Application label reads a message from the active translation catalog:

```yaml
spec:
  label: '{{ Trans "applications.home.label" }}'
```

The outer single quotes belong to YAML. The action between `{{` and `}}` belongs to the Expression.
Quote the complete YAML value so braces, colons, and other Expression characters are not interpreted
as YAML syntax.

An Expression may also combine text and actions:

```yaml
children: "Welcome, {{ props.name }}!"
```

## Use Expression syntax

Inside an Expression, you can use actions, arguments, pipelines, variables, whitespace trimming,
and control structures.

| Need                           | Syntax example                                                   |
| ------------------------------ | ---------------------------------------------------------------- |
| Print a value                  | `{{ props.title }}`                                              |
| Combine text and a value       | `Hello, {{ props.name }}!`                                       |
| Pass a pipeline result         | `{{ props.title \| printf "%s" }}`                               |
| Compare values                 | `{{ if eq props.active true }}Active{{ else }}Inactive{{ end }}` |
| Set and reuse a local variable | `{{ $title := props.title }}{{ $title }}`                        |
| Change the current context     | `{{ with props.title }}{{ . }}{{ end }}`                         |
| Iterate a value                | `{{ range props.items }}{{ . }}{{ end }}`                        |

The examples show syntax, not permission to use every referenced name in every context. An Expression
must both parse successfully and use only functions and context values available where it runs.
Names and paths are case-sensitive.

<Callout title="Syntax and context are separate" type="info">
  `{{ props.title }}` is valid Expression syntax. It still fails when evaluated outside a context
  that exposes `props`, or when that context has no `title` prop.
</Callout>

## Global functions

Taskmigo exposes these functions anywhere a field accepts an Expression.

| Group | Functions |
| ----- | --------- |
| Translation | `Trans`, `TransN` |
| Boolean | `and`, `or`, `not` |
| Comparison | `eq`, `ne`, `lt`, `le`, `gt`, `ge` |
| Values and collections | `len`, `index`, `slice` |
| Formatting | `printf` |

`Trans` reads and formats a translated message; `TransN` selects a locale-aware plural message.

```yaml
description: '{{ Trans "applications.home.description" }}'
```

```yaml
description: '{{ TransN "cart.items" 3 }}'
```

See [Translation](/versions/v0/manifests/v0-translation) for catalog structure, placeholders,
plural selection, fallbacks, and errors.

## Global variables

Expressions can use these global variable roots:

- `.Runtime`
- `.This`

See [Context variables](/versions/v0/context-variables) for their available fields and when each
value is set.

## Context values

Context values are not global functions. Taskmigo exposes them only while evaluating the relevant
manifest area.

### Component props

A reusable Component declares its context under `spec.props`. Expressions within `spec.template`
can access those values through `props.<name>`:

```yaml
kind: v0/component
name: heading

spec:
  props:
    title:
      type: string
      required: true

  template:
    component: Typography
    props:
      variant: h1
    children: "Title: {{ props.title }}"
```

`props.title` exists because the same Component declares `spec.props.title`. `props` is unavailable
in a Page, Application, Site, or Translation manifest. A prop path that was not declared is invalid
when the template is evaluated.

## Support and context by manifest kind

First check whether the exact field accepts an Expression. If it does, the full template syntax is
available; only its context values vary.

| Kind             | Fields that accept Expressions                                                                                 | Additional context values      |
| ---------------- | -------------------------------------------------------------------------------------------------------------- | ------------------------------ |
| Common fields    | None                                                                                                           | None                           |
| `v0/site`        | None                                                                                                           | None                           |
| `v0/application` | `spec.label`, `spec.description`                                                                               | None                           |
| `v0/page`        | `spec.meta.title`, `spec.meta.description`; component values when the component contract accepts an Expression | None                           |
| `v0/component`   | Values inside `spec.template` when the target component field accepts the resolved type                        | Declared `props.<name>` values |
| `v0/translation` | None; `spec.content` provides catalog data consumed by `Trans` and `TransN`                                    | None                           |

For example, [Typography children](/versions/v0/ui-components/typography) accept a string
Expression. A Component can use text, pipelines, conditions, or declared props there as long as the
rendered result is a string accepted by `Typography.children`.

<Callout title="Identity and structure remain literal" type="warn">
  `kind`, `name`, `version`, `imports`, field names, resource references, routes, and component
  names do not accept Expressions unless their contract explicitly says otherwise. Template syntax
  cannot generate manifest structure.
</Callout>

## Validation checklist

Before saving a manifest that contains an Expression, check that:

1. The exact field accepts an Expression.
2. The complete YAML scalar is quoted when template characters could be interpreted by YAML.
3. The Expression follows Taskmigo syntax and every action is closed.
4. Every referenced function or context value is available in that field's evaluation context.
5. The rendered value matches the type required by the field or component contract.

Parsing validates syntax. Evaluation can still fail because a function or context value is
unavailable, a path is missing, a function receives invalid arguments, or the rendered value has
the wrong type.
