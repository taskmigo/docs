---
title: Expressions
description: Put dynamic text or values into fields that accept an Expression.
---

Use an Expression when a field needs a value that Taskmigo can resolve while it evaluates the
manifest: translated text, the current manifest identity, or the runtime hostname.

## Start here

Write an Expression between `{{` and `}}`. Quote the complete YAML value.

```yaml
spec:
  label: '{{ Trans "applications.home.label" }}'
```

In this example:

- `'...'` is the YAML string.
- `{{ ... }}` is the Expression.
- `Trans` is a global function.

<Callout title="Use Expressions only where a field allows them" type="info">
  Expression syntax is not valid in every YAML field. Check
  [where Expressions are supported](#where-expressions-are-supported) before adding one.
</Callout>

## Choose what you need

| I want to… | Start with |
| --- | --- |
| Show text from a translation catalog | [Translate a message](#translate-a-message) |
| Change text for a count | [Translate a quantity](#translate-a-quantity) |
| Use the Site hostname or current manifest metadata | [Use context values](#use-context-values) |
| Format, compare, or transform a value | [Use built-in functions](#use-built-in-functions) |

## Translate a message

Use `Trans` with a catalog key. Additional values fill the message placeholders.

```yaml
description: '{{ Trans "applications.home.description" }}'
```

For catalog structure, placeholders, fallbacks, and errors, see
[Translation](/versions/v0/manifests/v0-translation#translate-a-message).

## Translate a quantity

Use `TransN` when the catalog message changes for a quantity.

```yaml
description: '{{ TransN "cart.items" 3 }}'
```

The second argument is the count. Taskmigo selects the locale's plural form. See
[Translation](/versions/v0/manifests/v0-translation#translate-a-quantity) for the complete rule.

## Use context values

| Value | Available in | Returns |
| --- | --- | --- |
| `.Runtime.Hostname` | Any Expression | Hostname at evaluation time |
| `.This.kind` | Any Expression | Current manifest kind |
| `.This.name` | Any Expression | Current manifest name |
| `.This.version` | Any Expression | Current manifest version |
| `.This.revision` | Any Expression | Current manifest revision |
| `props.<name>` | Component `spec.template` | A prop passed to that Component |

Use `props.<name>` only in a Component template. To declare or pass props, see
[Component](/versions/v0/manifests/v0-component#fields).

## Use built-in functions

These global functions are available wherever a field accepts an Expression.

| Need | Functions | Example |
| --- | --- | --- |
| Combine boolean conditions | `and`, `or`, `not` | `{{ if and props.enabled props.visible }}Shown{{ end }}` |
| Compare values | `eq`, `ne`, `lt`, `le`, `gt`, `ge` | `{{ if eq props.variant "primary" }}Primary{{ end }}` |
| Count a value | `len` | `{{ len props.items }}` |
| Select a value | `index` | `{{ index props.items 0 }}` |
| Select a range | `slice` | `{{ slice props.items 0 2 }}` |
| Format a value | `printf` | `{{ printf "Hello, %s" props.name }}` |

## More Expression syntax

Expressions can also use pipelines, local variables, conditions, and iteration.

| Need | Syntax example |
| --- | --- |
| Pass a result to another function | `{{ props.title \| printf "%s" }}` |
| Store and reuse a value | `{{ $title := props.title }}{{ $title }}` |
| Render only when a condition matches | `{{ if props.active }}Active{{ else }}Inactive{{ end }}` |
| Iterate a value | `{{ range props.items }}{{ . }}{{ end }}` |

Names and paths are case-sensitive.

## Where Expressions are supported

First check the exact field. When it accepts an Expression, you can use the syntax above; the
available context values still depend on where Taskmigo evaluates it.

| Manifest kind | Fields that accept Expressions | Extra context |
| --- | --- | --- |
| Common fields | None | None |
| `v0/site` | None | None |
| `v0/application` | `spec.label`, `spec.description` | None |
| `v0/page` | `spec.meta.title`, `spec.meta.description`; component values when that component field accepts an Expression | None |
| `v0/component` | Values in `spec.template` when the target component field accepts the resolved type | Declared `props.<name>` |
| `v0/translation` | None; `spec.content` is catalog data used by `Trans` and `TransN` | None |

<Callout title="Manifest structure stays literal" type="warn">
  `kind`, `name`, `version`, `imports`, field names, resource references, routes, and component
  names do not accept Expressions unless their field contract explicitly says so.
</Callout>

## Before you save

1. Confirm that the exact field accepts an Expression.
2. Quote the YAML value when it includes Expression syntax.
3. Use only functions and context values available in that field.
4. Ensure that the evaluated result matches the field's required type.
