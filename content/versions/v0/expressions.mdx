---
title: Expressions
description: Use dynamic values safely in Taskmigo YAML manifests.
---

An expression tells Taskmigo to calculate a field instead of using the YAML text literally. Use an
expression only in a field whose manifest or component contract explicitly accepts it.

## Start with one expression

This Application label reads a message from the active translation catalog:

```yaml
spec:
  label: '{{ Trans "applications.home.label" }}'
```

The outer single quotes belong to YAML. The content between `{{` and `}}` is the Taskmigo
expression. Quoting the complete value keeps YAML from interpreting the braces as YAML syntax.

<Callout title="An expression replaces the complete value" type="info">
  Use a documented expression as the entire YAML scalar. Combining literal text and an expression,
  such as `title: 'Welcome {{ props.name }}'`, is not defined. Put the complete message in a
  translation or pass the complete value as a prop instead.
</Callout>

## Available expressions

| Expression                           | Outcome                                            | Available context                    |
| ------------------------------------ | -------------------------------------------------- | ------------------------------------ |
| `{{ Trans "key" ...values }}`        | Reads and formats one translated message.          | Fields that accept `TransExpression` |
| `{{ TransN "key" count ...values }}` | Selects and formats a locale-aware plural message. | Fields that accept `TransExpression` |
| `{{ props.<name> }}`                 | Reads one typed prop supplied by a Page.           | `v0/component` `spec.template` only  |

Expression names and paths are case-sensitive. `Trans`, `TransN`, and `props.title` cannot be
written as `trans`, `transN`, or `props.Title` unless that exact prop name was declared.

### Translate text with `Trans`

```yaml
description: '{{ Trans "applications.home.description" }}'
```

The quoted key is a dotted path in the effective locale catalog. Additional values fill the
message's formatting placeholders from left to right.

### Translate a quantity with `TransN`

```yaml
description: '{{ TransN "cart.items" 3 }}'
```

The numeric argument selects a CLDR plural category and also fills the first compatible
placeholder. See [Translation](/versions/v0/manifests/v0-translation#translate-a-quantity) for
catalog structure, placeholder rules, fallbacks, and errors.

### Read Component props

A reusable Component declares the values it accepts in `spec.props`. Its template can read each
value by its declared name:

```yaml
kind: v0/component
name: heading

spec:
  props:
    title:
      type: string
      required: true

  template:
    component: Typography
    props:
      variant: h1
    children: "{{ props.title }}"
```

`props.title` is available because `spec.props.title` declares it. It is not a global variable and
is not available in a Page, Application, Site, or Translation manifest.

## Expression support by manifest kind

Start from the kind, then check the exact field. A kind supporting one expression does not make
expressions valid in all of its fields.

| Kind             | Fields that accept expressions                                                                                        | Available expressions                                              |
| ---------------- | --------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| Common fields    | None                                                                                                                  | None                                                               |
| `v0/site`        | None                                                                                                                  | None                                                               |
| `v0/application` | `spec.label`, `spec.description`                                                                                      | `Trans`, `TransN`                                                  |
| `v0/page`        | `spec.meta.title`, `spec.meta.description`; component values only when their component contract accepts an expression | `Trans`, `TransN`                                                  |
| `v0/component`   | Values inside `spec.template` only when the target component field accepts the resolved type                          | `props`; `Trans` or `TransN` where a translated string is accepted |
| `v0/translation` | None; `spec.content` defines the values that translation expressions read                                             | None                                                               |

For example, [Typography children](/versions/v0/ui-components/typography) accept a string or a
translation expression. A Component may therefore place `{{ props.title }}` there when `title` is
declared as a string. A boolean prop cannot be placed there because its resolved type is not a
string.

<Callout title="No expression in common identity fields" type="warn">
  `kind`, `name`, `version`, `imports`, and resource references are literal YAML values. Expressions
  cannot generate resource identities, dependencies, routes, field names, or component names.
</Callout>

## Validation checklist

Before saving a manifest that contains an expression, check that:

1. The complete expression is quoted as one YAML scalar.
2. The field's contract accepts that expression and its resolved value type.
3. Every `props.<name>` path matches a declaration in the same Component's `spec.props`.
4. Every translation key and placeholder value follows the [Translation contract](/versions/v0/manifests/v0-translation).

Nested expressions, expression operators, string interpolation, conditional expressions, and
access to undeclared runtime objects are not defined. See [Product status](/versions/v0/status#known-limitations-and-open-decisions).
