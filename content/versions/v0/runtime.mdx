---
title: Runtime lifecycle
description: Follow validation, dependency recovery, and snapshot activation.
---

## Validate

A revision becomes valid only after YAML parsing, common metadata, kind-specific schema, dependency resolution, graph, and security checks succeed.

Failed revisions retain structured diagnostics with the manifest path and, when available, source location. Diagnostics must not expose credentials, connection strings, or data from schemas Taskmigo does not own.

## Recover dependencies

Creating, updating, deleting, or importing a resource revalidates it and its reverse dependents.

```text
A imports B imports C

C becomes invalid
→ B becomes invalid
→ A becomes invalid

Fix C
→ validate C, B, then A
→ rebuild when the graph is valid
```

Unrelated branches remain valid. Recovery re-resolves existing declarations; it does not rewrite dependent manifests.

A translation change revalidates snapshots that use its locale catalog without requiring explicit translation import edges.

## Activate a snapshot

A Site snapshot contains the resolved revisions and normalized runtime model for the reachable graph. Separate branches may contribute different versions of the same resource identity.

```text
Change or package import
→ validate the affected graph
→ valid: build and atomically activate a snapshot
→ invalid: store diagnostics and keep the current snapshot
```

There is no manual activation state. New requests use the replacement snapshot; in-flight requests may finish on the previous one.

## Import and export packages

Export preserves canonical YAML. Import validates the complete portable package before creating revisions and cannot leave a partially active runtime state.
